# Sales Radar · 销售雷达 — 使用说明

> 版本：enterprise-match.v1 · 更新：2026-09-29
> 所属：AI / sales-radar
> 一句话：**输入产品信息与企业候选，自动输出"潜在客户打分排序 + 触达建议"**，帮助销售与市场从企业库（基本信息 / 招投标 / 官网战略 / 上下游关系）中挖掘高价值目标客户。

---

## 一、系统简介

| 项 | 说明 |
|---|---|
| 定位 | 潜在客户挖掘 / 企业-产品匹配评价（销售线索引擎） |
| 核心能力 | 双语企业评估（中文/国际）、六维原子化评分、域先验校正、置信度路由、打分排序与触达建议 |
| 技术底座 | JevP（System One 决策引擎） + qwen3.8-27b（GPU 服务器推理），可选 Laya / AgentJev 等判别式后端 |
| 数据维度 | 企业基本信息、招投标记录、官网战略与发展方向、上下游关系 |
| 评分标尺 | 0–3 分（0 无关 / 1 低匹配 / 2 中匹配 / 3 高匹配），另提供 0–100 百分位展示分 |

## 三、快速上手（销售 / 运营视角，5 步）

1. 浏览器打开调试台：`http://192.168.1.52:8022/`；
2. **产品信息**：页面默认带示例产品（Titan-PHM 预测性维护平台），改成你的产品即可（JSON：name + description）；
3. **企业列表**：三种方式任选——
   - 「加载中文示例 / 英文示例」一键体验内置企业；
   - 「＋添加模板企业」追加一家完整字段模板，**只改企业名称、行业、招投标标题**等关键字段；
   - 直接粘贴企业 JSON 数组（字段结构见第四章）；
4. 选择参数（默认即可）：问题集 `core`（3 问/家，性价比）、勾选"域先验校正"；
5. 点击「▶ 开始匹配」→ 得到排序表与触达建议，按「🔥 优先触达 → →可跟进 → ◇ 观察 → ✋ 暂不触达」顺序跟进。

**结果怎么读**：
- `匹配分`：0–3，越高越值得投入；`百分`：换算为 0–100 便于汇报；
- `置信度`：本次判断的把握，低于 0.7 的建议人工复核后再跟进；
- `↩校正`：命中域先验规则被强制降档（如"非企业实体""行业无关且无招投标"），属预期行为；
- 展开企业行可看六维明细（行业匹配 / 需求信号 / 采购体量 / 战略契合 / 紧迫度 / 综合匹配）。

## 四、输入说明

### 4.1 产品（可选，缺省用内置示例）
```json
{
  "name": "你的产品名称",
  "description": "面向哪个行业、解决什么痛点、目标客户特征（1~2 句话）"
}
```

### 4.2 企业档案（单个对象）
| 字段 | 类型 | 说明 | 是否必填 |
|---|---|---|---|
| `name` | string | 企业名称 | ✅ |
| `basic.industry` | string | 主营行业 | ✅ |
| `basic.scale` | string | 规模（大型/中型/小型/非企业等） | 建议 |
| `basic.location` | string | 地区 | 建议 |
| `basic.employees` / `since` | string / int | 人数 / 成立年 | 可选 |
| `bidding[]` | array | 招投标/采购记录：`{year, title, amount?}`，title 写清采购方向 | 建议（需求信号关键） |
| `website.strategy` | string | 官网/年报战略关键词（数字化、智能制造等） | 建议 |
| `website.news` | string | 近期动态（新产线、融资等） | 可选 |
| `supply_chain` | object | `customers` / `suppliers` / `leverage`（上下游与切入渠道） | 可选 |

> 填得越全，评分越准；最少 `name + basic.industry` 即可出分。模板可通过 `GET /api/match/template` 获取。

## 五、输出说明（ranking[] 每项）

| 字段 | 含义 |
|---|---|
| `name` | 企业名 |
| `lang` | `zh` / `en`（档案+问题混合判定） |
| `match_score` | **主分 0–3 连续小数**（排序键）：∑档位×概率 |
| `level` | 档位 0–3（`round(match_score)`） |
| `score_pct` | 百分位 0–100（= `match_score/3*100`，展示/汇报用） |
| `score_raw` | 校正前原始分 |
| `patched` / `patch_note` | 是否被域先验校正 / 原因（如"行业无关且无招投标→≤0.5"） |
| `confidence` | 0–1 置信度（**未校准概率**：作排序/阈值信号可用；作概率自动化前建议温度缩放校准） |
| `margin` | top1−top2 概率差（越大越坚决） |
| `advice` | 触达建议：🔥优先触达 / →可跟进 / ◇观察待唤醒 / ✋暂不触达 |
| `per_question` | 各评估问题明细（含概率分布与 raw_mass） |

`meta`：使用的后端、调用次数估算、耗时。

## 六、评分口径与使用建议

- **匹配分 0–3 不是百分制**：内部保留 0–3 是为了"档位语义可解释 + 与标注同尺度可评测 + 避免伪精度"；百分位是展示层换算，二者一一对应；
- **置信度与分数不要混用**：分数=匹配强弱，置信度=判断把握。建议：`高置信(≥0.9) 且 高分(≥2.5)` 才自动进入触达队列，其余转人工（页面已按此给出建议）；
- **降频/批量**：v2 支持 `mode=full` 全量评分，以及 `mode=topk` 先召回、粗排再精评。`min` 在开启校正时为 2 问/家，关闭校正时为 1 问/家；具体调用量还受缓存命中影响。大批任务使用异步作业，见 [性能与批量 API](MATCHING_PERFORMANCE.md)；
- **校准**：如需把 `confidence` 当概率做自动化（如 0.9 才放行），请提供 200–500 条历史标注做温度缩放校准（系统内置 `calibrator`，输出 ECE 报告）。

## 七、API 集成（开发视角）

基础地址：`http://192.168.1.52:8022`

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/match` | POST | 批量打分+排序（输入见四章） |
| `/api/match/one` | POST | 单企业快查（正文即企业对象） |
| `/api/match/example?lang=zh\|en` | GET | 内置 8 中 / 6 英示例 |
| `/api/match/template` | GET | 输入默认模板 |
| `/api/schema` | GET | 输入/输出结构契约 |
| `/healthz` | GET | 健康检查 |

请求体示例（Python）：
```python
import requests
r = requests.post("http://192.168.1.52:8022/api/match", json={
    "product": {"name": "…", "description": "…"},
    "companies": [{"name": "…", "basic": {"industry": "…"}, "bidding": [], ...}],
    "questions": "core", "apply_patch": True, "backend": "auto",
})
print(r.json()["ranking"][:3])
# 完整契约：GET /api/schema
```

## 八、常见问题（FAQ）

**Q1 打开地址提示登录/无法访问？** 本系统跑在服务器内网，需在可访问 192.168.1.52 的网络内；公网访问需管理员网关转发 + 鉴权。

**Q2 分数含义？为什么有的企业显示 0.5？** 0–3 档位分；0.5 是域先验校正的封顶值（"行业无关且无招投标→≤0.5"或"非企业实体→≤0.5"），表示落 0 档方向但保留轻微线索。

**Q3 置信度 0.98 但建议是"暂不触达"？** 正常——建议同时看分数与置信度（低分高置信=明确不该投入，如"味全"1.04 分）；高分低置信=有潜力但不把握，建议人工复核。

**Q4 企业档案怎么最快填？** 「＋添加模板企业」拿到完整字段模板，只改 `name`、`basic.industry`、`bidding[].title` 即可。

**Q5 大量企业怎么处理？** 先用 `POST /api/companies/index` 构建可复用索引，再以 `index_id` 提交 `/api/match/jobs`。需要每家都得到 JEV 分数时选 `full`；仅寻找重点客户时可用 `topk`，默认召回池最多 5,000 家、精评 500 家、返回前 100 家。响应会标明覆盖范围，筛选不保证全库最优。详见 [性能与批量 API](MATCHING_PERFORMANCE.md)。

**Q6 Windows 下用 curl 调 API 报 JSON 错误？** PowerShell 的引号转义与 Linux 不同，推荐用 Python / JSON 工具构造请求（见第七章示例）。
