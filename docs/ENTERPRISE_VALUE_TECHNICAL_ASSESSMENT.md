## 1. 评估结论与使用边界

**当前方案能够更高效地表达“企业资料与产品描述之间的潜在适配性”，但尚不能可靠代表企业的真实潜在商业价值。**

更准确的产品定位是：**有明确覆盖范围的客户线索检索、初筛与人工研判辅助系统**。
当前证据支持工程管线在合成数据上的可用性，不支持把输出解释为成交概率、预计收入、客户终身价值或供应链贡献。

| 决策问题 | 当前支持程度 | 理由 |
|---|---|---|
| 从大量档案中找出值得进一步调查的企业 | 可以作为初筛工具试用 | 已有召回、精评、缓存及错误隔离；真实排序质量待验证 |
| 解释为什么某企业可能适合某产品 | 部分支持 | 有分项答案，但没有逐条证据引用和完整组合评分依据 |
| 证明该企业现在存在真实采购需求 | 不足 | 接收外部资料，没有完成来源核验、时效判定及采购角色确认 |
| 估计指定周期内的成交概率 | 不支持可信概率解释 | 未以该业务结果定义标签、训练及独立校准 |
| 估计客户带来的收入、贡献利润或回款价值 | 未建模 | 缺少客单价、交付成本、赢单/回款结果及成本归因 |
| 衡量渠道、上游或下游的间接价值 | 未形成结构化模型 | 供应链目前主要作为自由文本输入 |
| 在销售资源有限时选择最值得投入的客户组合 | 未实现 | 尚未优化预算、销售工时、集团重复或渠道冲突等约束 |

“未验证”不等于“必然无效”；它意味着目前没有足够证据作出相应业务承诺。
本轮性能优化应当保留，但下一轮应优先补上目标、证据和真实验证，而不是继续单独追求更快的评分。

数据采集与证据工程的具体执行要求见
[企业关键信息采集规范](ENTERPRISE_DATA_COLLECTION_SPEC.md)，可直接用于数据工程任务拆分。

## 2. 首先定义“谁眼中的价值”

企业没有一个脱离情境的通用潜在价值分。评价单位应至少是：

```text
供应方 × 产品/方案版本 × 企业/集团/工厂/项目 × 合作角色 × 行动方式 × 评价日期 × 观察周期
```

例如，某企业可能不是设备终端采购方，却是设备 OEM、渠道商或影响客户选型的集成商；
也可能高度适配产品，但现有供应商合同尚未到期、无导入资格或交付成本过高。

建议将目标拆成五类，分别输出，再根据具体业务选择排序目标：

| 目标 | 回答的问题 | 需要的独立证据 |
|---|---|---|
| 适配价值 | 产品能否解决该企业的具体问题？ | 场景、技术条件、痛点、替代方案 |
| 机会价值 | 在周期 H 内是否存在可推进商机？ | 采购阶段、预算状态、联系人、窗口、采购权限 |
| 经济价值 | 可能产生多少净贡献，需投入多少资源？ | 条件客单价、交付/支持成本、回款、售前投入 |
| 网络价值 | 是否能够帮助进入其他企业或项目？ | 有方向、有时间及来源的渠道/客户/供应关系 |
| 信息价值 | 再调查或接触一次，能否显著改善决策？ | 不确定项、补证成本、信息可获得性 |

真实需求可能无法从公开资料完全观测。模型应估计与表达这种不确定性，不能把“没有搜到”当成“没有需求”。

## 3. 当前架构：哪些做法值得保留

当前路径为企业索引、混合召回与加权排序、候选 JEV 评价、规则校正、结果排序；
外加批处理、HTTP 并发上限、缓存和异步作业。

| 已实现能力 | 对后续价值评估的作用 | 仍需注意 |
|---|---|---|
| 产品进入 `scoring_state` | 可以按具体产品判断企业，而非固定 PHM 模板 | 产品的价格、技术门槛和服务区域仍需结构化 |
| `full` 与 `topk` 明确区分 | 避免把局部候选结果当成全库评价 | 全库评分也不等于真实标签或无遗漏企业库 |
| 独立索引与分批推理 | 降低重复处理成本，支持规模化试验 | 客户端并发不直接证明实际模型吞吐 |
| 版本化缓存 | 减少重复评价，有利于复现实验 | 档案不更新时，缓存失效也不会主动获取新事实 |
| 企业级错误隔离及输入位置对齐 | 提高运行可控性，避免重名导致结果错配 | 仍需要法律实体、集团、工厂和项目的实体消歧 |
| 采购证据单独召回 | 比仅靠同类产品关键词更接近买方识别 | 招标可能过期、由代理发布，或已经完成采购 |
| 候选探索 | 给部分资料不完整企业保留机会 | 当前是固定种子的候选探索，不是线上因果试验 |

实现依据：[匹配管线](../jevp/matching.py)、[召回索引](../jevp/retrieval.py)、
[性能说明](MATCHING_PERFORMANCE.md)。

## 4. 关键缺口及代码证据

### F01：缺少可检验的业务目标，P0

当前最终排序主要依据 0–3 的 `match_score`，没有指定未来结果事件、观察周期、行动和经济收益。
即使“匹配分”排序正确，也无法直接回答“应给谁分配销售工时”或“谁能产生更多贡献利润”。

**迭代要求：**先选一个主目标，例如“在未来 180 天，经标准化销售流程形成合格商机”或
“在未来 365 天产生净回款贡献”。不同目标分别建标签和模型版本，不把它们混在一个准确率中。

### F02：分项结果没有显式合成为综合分，P0

`build_match_questions` 定义了行业、需求、预算、战略、紧迫性和综合匹配问题。
但 `result_row` 直接读取独立的 `match_score`，再按行业和特定商业主体规则封顶；
需求、预算、战略及紧迫性的**分项输出**没有进入显式加权或学习到的组合函数。

综合问题仍可以从原始企业资料中间接考虑这些因素，因此不能断言模型完全忽略了它们。
问题在于：各项贡献不可审计，没有一致性、单调性和缺失处理的程序化保证。

本次最小反例保持综合输出不变，把需求、预算、紧迫性分项改为低值，最终分仍是 `2.8 → 2.8`。
这是输出处理逻辑的性质，不是真实模型准确率测试。

**迭代要求：**将原子问题用于提取特征，另用版本化组合器生成业务分。
无训练数据时可先用专家权重并显示适用范围；有结果标签后再比较线性模型、排序树或其他监督模型。
独立综合问题可以保留为交叉检查信号，不应冒充经过验证的特征组合。
TypeSafe 官方的组合评分模式也建议由代码控制维度组合。[官方组合评分说明](https://docs.typesafe.ai/patterns/composite-scoring)

### F03：置信度、匹配分和成交概率的含义没有贯通，P0

当前词表路径用候选概率的最大值作为 `confidence`，用档位期望作为 `score`；
`score_pct` 是 `score / 3 × 100` 的展示映射，既不是百分位排名，也不是成交率。
不同 direct 后端还可能具有不同的 confidence 定义，不能默认共用相同阈值。
0/1/2/3 的适配等级也不代表经济收益等距，档位期望可作排序信号，不能直接解释为收益期望。

仓库有 `TemperatureScaler` 和 ECE 工具，但企业匹配 API 没有载入真实业务校准产物。
现有“优先触达”等建议中的 0.9/0.7 阈值，没有本场景成交或商机标签验证。
排序时以 confidence 作为平分后的次排序键，也可能优先资料丰富且模型熟悉的企业，而非商业价值更高的企业。

**迭代要求：**分开输出 `raw_model_confidence`、证据充分性、预测误差/不确定性和业务结果概率。
校准“专家匹配等级”的概率不会自动变成“未来成交”的概率；两者标签不同。
原始研究表明神经网络概率需要单独检验校准，但任何校准方法都需要与目标一致的独立数据。
[Guo 等，ICML 2017](https://proceedings.mlr.press/v70/guo17a.html)

### F04：top-k 候选缺失可能制造过度确定的答案，P0

HTTP 评分路径把未出现在 top-k 的候选 logprob 设为 `-100`。
这只是近似，不等于该候选真实概率接近零；后端也没有把“所有候选均被评分”作为契约返回。

离线数值反例：返回 `Yes=-3.0, Other=-0.1`，而 `No` 未返回时，当前计算得 `p_yes≈1.0`；
如果未返回的 `No` 实际为 `-3.1`，两个候选间归一化后的 `p_yes≈0.525`。
后一个值是用于展示不确定性的假设，不是从缺失数据中恢复出的真值。
当前近似 `raw_mass≈0.0522`，不是零，因此不会触发 `result_row` 的零 mass 拒绝条件。

`raw_mass` 在不同后端还分别代表完整词表份额或返回 top-k 内的相对份额，不能直接混用阈值。
此外，多 token 标签冲突时改选后续 token，并不等价于计算完整标签序列的条件概率。

**迭代要求：**使用经过验证的单 token 答案映射和候选级打分契约，显式返回候选覆盖状态；
缺失候选时保留未知、重试或切换支持该评分契约的后端。
需确认服务是否返回完整候选 logits/条件分数，不能只依赖接口名称。
单纯增加 `top_logprobs` 或套温度缩放不足以保证修复缺失候选的信息损失。

代码依据：[字符串评分及标签映射](../jevp/engine.py)、[HTTP 后端](../jevp/backend.py)。

### F05：硬阈值将模糊判断放大为业务否决，P0

当前 `industry_fit < 0.5` 会把综合分封顶为 1；最小反例中，行业输出从 0.49 改为 0.51，
同样的原始综合分 2.8，最终结果从 1.0 跳到 2.8。
这种边界突变可能遮蔽临近行业、跨行业应用和资料缺失企业的价值。

`commercial_only` 目前通过 `industry/scale` 的字符串片段识别主体。
最小反例中，`industry="research services"`、`scale="commercial private company"` 的企业，
会被按非商业客户封顶 0.5。该例证明规则存在误伤路径，不代表其实际误伤率已知。

**迭代要求：**仅将已核验的硬要求作为否决条件；未知、矛盾和一般低置信判断走补证或软约束。
商业主体属性应来自实体字段与证据，不由行业字符串代替。
针对可核验的必要条件做严格约束；针对相关性和适配性使用可验证的连续特征。

### F06：缺少事实来源、双时间和未知状态，P0

当前输入主要是自由文本，没有强制的证据 ID、来源、发布日期、采集时间、适用主体或失效状态。
`as_of` 被传给模型并进入缓存键，但召回没有据此过滤未来资料或过期公告。
仅改变 `as_of`，不构造当时实际可获得的档案快照，不能形成可信历史回测。

应区分：事件发生时间、该信息首次可被系统获知的时间、适用/失效时间。
历史样本只能使用评价时已经可获得的资料；迟到公告即使描述了更早事件，也不能回填到更早特征中。

**迭代要求：**每个关键结论关联证据及 `supported / refuted / unknown / conflicting` 状态。
核实事实、推断需求、预测结果分别存储；缺失预算不等于预算为零。
同一新闻的多站转载应去重，不能当成多个独立需求信号。

### F07：召回预算是效率设计，不是高价值客户覆盖保证，P1

当前采用 BM25、中文双字词、可选向量和人工设定的融合权重。
同义表述、工艺术语、中英跨语言、隐性需求和低曝光企业均可能在精评前被漏掉。
当前词项提取对文本前 12,000 字符取词，也存在证据位置导致的遗漏路径。
已采购完毕的公告仍可能被较高权重召回，不能将历史采购活跃直接解释为当前机会。

默认 500 个精评位中约 50 个为探索；在 10 万家企业中，这并不等于覆盖了 10% 全库。
固定种子使同一索引和产品的探索结果重复出现，不会随着重复查询自动扩大探索覆盖。
探索候选也未必进入最终 Top-100，更不等于企业被实际接触。

**迭代要求：**对被排除的企业做有记录的分层抽样审计；按产品、行业、资料完整度和角色测漏召回。
保存各召回通道分数、原因、预算和探索策略版本；需做统计估计时记录实际抽样概率。
语义重排和查询扩展均应通过留出集验证，不预设更复杂模型必然更好。

### F08：供应链关系尚未形成可计算的结构，P1

`supply_chain` 进入的是文字上下文，没有主体消歧、有方向关系、有效期及证据链。
无法可靠区分使用者、付款者、采购代理、OEM、经销商、集成商和采购影响者。
同样不能区分集团总部、分厂与同一项目中的多家参与方，可能重复计算商机或收入。

**迭代要求：**先建设可查证的关系表和规则路径，再决定是否需要图学习模型。
相邻企业、知名客户或高中心性只说明关系特征，不直接证明会给当前产品带来订单。

### F09：业务反馈和资源分配尚未闭环，P1

当前没有记录候选为何被展示、谁实际联系了企业、投入了多少资源、结果何时成熟。
若未来只用高分企业的销售结果训练，就会把现有策略的选择偏差继续学进去。
未被接触、未回复和观察期未满，均不能简单标为“无价值”。

推荐/排序研究说明了观察反馈存在选择与展示偏差；本项目借鉴的是方法原则，并非引用这些论文证明 B2B 成交效果。
[Schnabel 等，ICML 2016](https://proceedings.mlr.press/v48/schnabel16.html)，
[Joachims 等，WSDM 2017](https://www.cs.cornell.edu/~tj/publications/joachims_etal_17a.pdf)

**迭代要求：**记录推荐、展示、人工选择、接触动作、成本、商机阶段、结果及截尾状态。
业务上线后比较单位销售工时带来的合格商机和净贡献，而不是只比较平均匹配分。

## 5. 建议的价值模型

### 5.1 先采用分层输出，避免一个分数包揽所有含义

| 输出层 | 推荐字段 | 业务含义 |
|---|---|---|
| 事实与约束 | 主体角色、技术要求、地域、采购阶段、证据状态 | 哪些事实已知，哪些条件明确满足/不满足 |
| 适配判断 | 产品场景适配、痛点强度、可替代性、导入难度 | 是否值得继续研究 |
| 商机预测 | `P(qualified_opportunity within H)`、`P(win within H)` | 以相应成熟标签校准后的事件概率 |
| 经济估计 | 条件订单规模、净贡献、售前成本及区间 | 潜在收益和所需资源 |
| 网络与组合 | 渠道路径、共享项目、集团归属、替代/互补关系 | 避免重复计量，识别间接进入路径 |
| 决策建议 | 跟进、补证、观察、当前不投入 | 指定行动的预期收益及其不确定性 |

上述新增概率和金额尚未实现；没有相应数据时返回 `null/unknown`，不要把 0–3 分换算后填入。

### 5.2 从适配分走向可核算的经济价值

有足够 CRM 数据后，可先建立与现行行动流程相关的近似模型：

```text
EV(i, p, a, H)
  ≈ P(在 H 内赢单 | 当前特征, 指定销售流程 a)
    × E(净回款贡献 | 在 H 内赢单, 当前特征, a)
    − E(售前及获客成本 | 当前特征, a)
```

“净回款贡献”须统一口径：回款收入减去相应的交付、实施、支持等可变成本；
这些成本若已包含在贡献中，不应再次扣减。未回款风险若已通过净回款目标体现，也不能再重复打折。
与成交相关的后续成本、退款或跨期收入，应明确观察窗口和归属规则。

以下仅为算术示例，概率与金额均为假设，不能由现有 JEV 分数推导：

| 企业 | 适配分示意 | 假设赢单概率 | 赢单后净回款贡献 | 售前/获客成本 | 近似 EV |
|---|---:|---:|---:|---:|---:|
| A，大型高适配客户 | 2.9 | 10% | 120,000 元 | 18,000 元 | -6,000 元 |
| B，中型可落地客户 | 2.3 | 45% | 60,000 元 | 6,000 元 | 21,000 元 |

因此，高适配不必然等于高行动价值。没有结果数据时，可以提供透明的专家优先级，但不能宣称这些是假设之外的真实 EV。

### 5.3 最终应评估“行动带来的增量”

```text
增量价值 ΔV(a)
  = E[净贡献 | do(a), 当前可得信息]
    − E[净贡献 | do(基准行动), 当前可得信息]
    − 尚未计入净贡献的增量行动成本
```

普通赢单预测是关联性预测，不能自动解释为“联系该企业会造成多少收益”。
后续可借助随机试验或满足可识别假设的因果方法估计增量；观察数据方法要求重叠、混杂控制等条件，不能仅换一个算法名称。
[Wager 与 Athey 的异质处理效应研究](https://arxiv.org/abs/1510.04342)

不要把行业适配、需求、预算等边际概率直接相乘；它们通常相关。
只有对定义清晰的嵌套商机阶段，才能使用相应的条件概率分解，并仍需对最终概率校准。

## 6. 供应链视角下的最小模型

### 6.1 关系结构

| 实体/关系 | 最少字段 | 对决策的意义 |
|---|---|---|
| 企业、集团、工厂、项目 | 唯一 ID、归属、地点、有效期 | 明确是谁使用、采购和付款 |
| `supplies_to` | 供应方、采购方、品类、时间、证据 | 区分提供相似产品与需要采购产品 |
| `uses_asset/process` | 工厂、设备/工艺、规模、时间 | 判断产品可作用的真实场景 |
| `procures_for` | 代理/总部、实际需求方、项目、权限 | 避免公告发布者与买方混淆 |
| `integrates/distributes` | 伙伴、覆盖客户、授权/地域、交易路径 | 判断渠道与集成商的进入价值 |
| `has_contract_with` | 产品类别、期限、替换条件、证据 | 估计竞争壁垒和采购时机 |

每条边需标注事实/推断、来源、可得时间和失效状态。
建议先实现关系表、实体归并和少量可解释路径查询，再与纯文本基线比较。

### 6.2 间接价值和重复计量

渠道价值应考虑真实可触达客户、转化路径、分成、支持成本和客户重叠。
同一集团、项目或渠道带来的最终订单只能按预先定义的归因口径计一次。
企业同时售卖相似方案，并不意味着完全无价值：它可能采购组件、联合交付或成为替代渠道。

多产品竞争同一预算、同一销售工时约束、区域交付能力和集团集中采购都可能使独立企业排序失效。
应最终优化客户/项目/行动组合；按 EV/工时排序可作启发式基线，但一般不保证最优解。

## 8. 如何证明方案体现了真实价值

### 8.1 四层验证必须分开

| 层次 | 主要验证 | 当前状态 |
|---|---|---|
| A，软件正确性 | 批处理一致性、缓存失效、错误隔离、排序与分页契约 | 已有 116 项离线测试记录 |
| B，判断有效性 | 真实证据下与独立专家标签的一致性、证据支持、未知处理 | 缺少独立真实数据验证 |
| C，结果预测性 | 按时间留出的商机/成交预测、分群校准、经济估计误差 | 未验证 |
| D，行动有效性 | 与基准策略相比的增量商机、净贡献和单位工时收益 | 未验证 |

当前不能用 A 层通过替代 B/C/D 层验收。

### 8.2 正确认识现有规模报告

[现有报告](MATCHING_BENCHMARK.md)记录了 10 万行合成企业、30 万题降至 1,500 题、
Top-100 重合率和 NDCG 为 1.0，以及缓存和增量失效结果。
这些结果证明受控管线行为，不证明现实企业价值。

原因包括：生成器按 `i % 100` 重复少数行业/需求/卖方组合；标签和 `SyntheticBackend`
采用相同场景规则；同一 fixture 的全量评分也不是真实世界金标准。
10 万行数据并不是 10 万个独立商业场景。NDCG 的满分可能只是规则与规则的一致。
实现依据：[生成器、fixture 和指标计算](../benchmarks/benchmark_matching.py)。

### 8.3 建立独立验证集

建议先做一个有边界的审计集，例如 3–5 个差异明显的产品、每产品 500–2,000 个企业—产品对；
这只是工作量规划起点，不是统计充分性的保证。实际规模需依据正例率、目标误差和产品/行业分组设计。

样本应覆盖：同行卖方、代理、渠道、跨行业应用、无公开采购但有痛点、已完成采购、
大型低可进入客户、中小高可落地客户、集团/工厂重复、资料缺失及相互矛盾证据。
每个样本标注事实支持、合作角色、适配、机会、未知原因；专家独立盲评后仲裁。
专家匹配标签和实际成交标签分开保存。

数据切分至少包括时间留出、同集团去泄漏、产品留出；
校准集、调参集和最终测试集不得反复混用，历史回测必须使用当时可得的证据快照。

### 8.4 指标与边界

| 指标 | 正确用途 | 常见误用 |
|---|---|---|
| Recall@候选预算 | 有已知正例分母时衡量候选漏失 | 将与全量模型结果一致当成真实召回 |
| NDCG@K / Precision@K | 用独立相关性或价值标签评估排序 | 以模型自身输出作为金标准 |
| 价值加权召回 | 检查被漏掉的已验证高价值机会 | 用未校准匹配分冒充经济价值权重 |
| Brier / log loss / 可靠性图 | 对明确定义的事件概率检查质量 | 用分类校准证明金额或因果正确 |
| ECE | 辅助查看概率与频率偏差 | 仅凭一个 ECE 数字忽略分箱、样本量与分群 |
| 证据准确性/未知处置 | 检查结论被来源支持、矛盾与拒答 | 为了覆盖率强制每家输出确定分 |
| 单位工时商机/净贡献 | 评价销售资源配置 | 仅以打开率、平均匹配分替代收入或贡献 |

概率校准需结合严格概率评分和可靠性图；单一分数不足以描述全部性质。
[scikit-learn 官方校准说明](https://scikit-learn.org/stable/modules/calibration.html)

全库无法穷尽标注时，应对排除集进行具有已知抽样设计的审计，报告加权估计、方差和覆盖假设；
小样本随机检查未发现漏召回，不能证明 10 万家无漏失。
所有关键差异报告置信区间，按产品、集团或其他实际相关单元做分组统计，避免将重复档案视为独立证据。

### 8.5 建议的上线门槛

以下是需与业务共同确认的**初始验收建议**，不是行业标准或本项目已达到的结果：

1. P0 数值反例和硬规则误伤路径均有修复及回归测试；缺失候选不再输出伪确定概率。
2. 在边界清晰的人工审计集上，候选 Recall@500 的试点目标可设为至少 95%；同时给出区间和分群结果。
   实际阈值需按错过一个高价值客户的代价调整，不能扩展声称为全库真实召回率。
3. 在独立测试集上至少不劣于最佳简单基线，并在预先指定的主指标上展示有统计支持的提升；
   不只与自己生成的标签或评分比较。
4. 需要输出业务概率时，先定义事件和周期，检验分群校准、区分能力及决策成本；
   不采用脱离样本量与误差成本的统一 ECE 或 confidence 阈值。
5. 自动分配大量销售资源前，通过与现行策略的对照试点验证净贡献或合格商机效率。
   销售周期未结束的样本标记为未成熟，不能提前记失败。

线上试点尽量以企业集团/项目为分配单元，避免同一集团被多策略重复接触造成干扰；
记录渠道、销售能力和执行差异。试验窗口与样本量按业务周期及功效分析确定。

## 9. 建议迭代路线与完成定义

本文 P0 表示下一轮应优先定义或修复的价值评估基础，P1 表示真实试点需要形成的闭环，
P2 表示依赖更多成熟数据的后续能力；这些是研发优先级，不是对线上事故严重性的评级。

| ID | 优先级 | 工作项 | 完成定义 | 依赖 |
|---|---|---|---|---|
| VAL-01 | P0 | 固化目标、主体、行动和观察周期 | 每个目标有标签定义、时间口径、成功/失败/未知处理 | 业务负责人确认 |
| VAL-02 | P0 | 修正候选概率契约 | 已知全候选分数对照通过；缺失候选明确未知或降级 | 后端评分能力确认 |
| VAL-03 | P0 | 分项组合与不确定性分离 | 显式组合版本、贡献说明、约束及缺失处理；边界反例回归 | VAL-01、VAL-02 |
| VAL-04 | P0 | 主体和硬条件核验 | 事实字段取代 research 等片段规则；未知不自动否决 | 实体与产品约束契约 |
| VAL-05 | P0 | 独立真实审计集 | 标签指南、盲评/仲裁、时间和集团切分、锁定测试集 | VAL-01 |
| VAL-06 | P1 | 证据与历史快照 | 重要结论可追溯；事件时间与可得时间分开；回测无未来信息 | 数据来源可用 |
| VAL-07 | P1 | 校准和分群评测 | 校准产物版本化，报告可靠性、误差区间和决策成本 | VAL-02、VAL-05 |
| VAL-08 | P1 | 召回审计与适应预算 | 排除集审计；固定预算与自适应预算做成本—质量比较 | VAL-05、VAL-06 |
| VAL-09 | P1 | CRM 与资源成本日志 | 推荐、执行、成本、阶段及成熟结果可关联 | VAL-01、业务流程接入 |
| VAL-10 | P2 | 供应链关系与去重 | 角色、路径和集团/项目合并通过独立对照评测 | VAL-04、VAL-06 |
| VAL-11 | P2 | 商机、赢单及经济模型 | 时间留出验证，金额口径、区间和校准明确 | 足够成熟的 VAL-09 数据 |
| VAL-12 | P2 | 增量与组合策略 | 有对照证据，考虑预算、交付能力、重叠和归因 | VAL-10、VAL-11 |

建议下一轮首先完成 VAL-01 至 VAL-05；保留现有吞吐架构。
在没有真实标签和成熟结果之前，不建议把蒸馏、大图模型或更大参数模型作为主要成功标准。

## 10. 风险登记与每次迭代的更新模板

| 风险 | 可观察信号 | 建议响应 |
|---|---|---|
| 大企业/资料丰富偏好 | 按档案长度、企业规模分组误差增大 | 做信息量匹配对照，检查证据与先验贡献 |
| 同业卖方误识别/合作机会误杀 | 角色冲突、多角色企业高误差 | 按产品和合作角色评估，不用单一公司类别替代 |
| 模型外部常识替代来源 | 匿名后评分明显变化，无法引用输入证据 | 做企业名遮蔽对照，要求结论支持证据 |
| 公告状态/时间错误 | 过期、终止、已中标公告仍高优先级 | 提取状态与有效期，加入反事实状态测试 |
| 资料中的指令干扰判断 | 加入“忽略评分规则”等文本后分数改变 | 把外部文本作为证据处理，做对抗与稳定性测试 |
| 策略反馈偏差 | 只联系高分客户，其他群体没有结果 | 记录展示和执行，设计受控审计/探索 |
| 数据分布变化 | 新行业或新产品上召回/校准下降 | 分群监控、重新标注与校准，保留回退基线 |
| 重复归因 | 同集团、项目或渠道出现多条预计收入 | 按经济主体和最终订单去重归因 |
